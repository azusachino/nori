# Changelog

## Unreleased

- **Course-wide assessments pool every lesson.** `<NoriAssessment banks={[...]} />` keeps each bank's own `lessonKey` on its exercises, so lessons that reuse exercise keys (`q-1` in each) sample together instead of failing with "The sample pool lists an exercise twice". With `banks`, an explicit `lessonKey` prop now only fills in for a bank that names none; with a single `bank` or inline `exercises` it still sets the lesson. The sidecar already identified pool items by `(lessonKey, exerciseKey)`; a true duplicate is still rejected. `poolBankExercises` is exported from the component module for this rule.

## 0.2.0

- **Streaming tutor (`POST /v1/tutor/stream`).** The tutor reply streams to `<NoriTutor />` over Server-Sent Events and shows as it arrives; the learner's question shows at once. A Cancel button aborts the request and the model call on the sidecar, saves nothing, and puts the question back in the box. `POST /v1/tutor` is unchanged and also cancels the model call when the client disconnects. `GET /v1/health` lists `features: ["tutor-stream"]`; `NoriClient.streamTutorMessage` uses the blocking call against an older sidecar. Deploy the sidecar first for streaming; older islands keep working.
- **Tutor history cap.** The model gets the last 12 turns, at most 24,000 characters (`historyLimit` in `GET /v1/tutor`), plus the lesson and selected attempts, never starting with an orphan reply. The island says when older turns were left out, on each reply and above the composer.
- **Readable long replies.** The tutor is asked for headings and lists on multi-part answers; a reply with three or more headings (or a long one with two) gets an "In this reply" jump list. `renderRichText` takes `headingIdPrefix`, and `extractHeadings` returns the matching ids. A line such as `# ` with no heading text no longer hangs the Markdown renderer.
- **Course progress (`GET /v1/progress`, `<NoriProgress />`).** Per lesson: exercises attempted, correct and due, attempts and the last activity, computed in SQL over the review queue's scoring. The new island takes an optional `lessons` list (titles, links, exercise counts) so untouched lessons show too. `NoriClient.getProgress`.
- **Answer due items in the review queue.** `<NoriReviewQueue />` answers each item with the same answer field as `<NoriPractice />` (multiple select, cloze and code included, not only a one-line retry). It records the answer with an attempt id, then shows the result, the reference answer and the next review date in place until dismissed. The answer field is now one shared component (`ExerciseAnswerField`) used by both islands.
- **Assessment sampling.** `POST /v1/assessments` takes `sample: { count, strategy: 'random' | 'weak', seed }` and draws from a pool of up to 500 exercises (body limit 1 MB); `weak` favours incorrect, due and unpractised exercises. The same seed and inputs draw the same items. `<NoriAssessment />` has a "Draw a sample" control with the seed shown after the draw, and a `banks` prop to pool several practice banks; each exercise keeps its bank's `lessonKey`. `NoriClient.createSampledAssessment`.
- **Feature list in `/v1/health`.** `features: ["tutor-stream", "progress", "assessment-sample"]`; the new client calls throw `NoriUnsupportedError` against an older sidecar instead of hitting a 404 or creating an unsampled assessment. Older islands are unaffected. Deploy the sidecar first.
- **Slim list views (`view=summary`).** `GET /v1/practice`, `/v1/review` and `/v1/assessments` accept `view=summary`, returning only what the islands render (no exercise snapshots, feedback text, reference answers or assessment items); `GET /v1/practice/attempts/{id}` fetches one attempt in full. The default responses are unchanged. The islands use the summary views (`listPracticeSummaries`, `getReviewQueueSummary`, `listAssessmentSummaries`, `getAttempt`) and load feedback, the prompt at attempt time, and a review retry's snapshot on demand. `nori:practice-updated` now carries attempt summaries.
- **Review queue in SQL.** The spaced-recall queue is ranked, scored and ordered in SQLite over a new covering index (`practice_attempts_review`, migration `0001`), reading the wide columns only for the rows returned; the recall digest counts attempts instead of loading them.
- **SQLite settings.** Connections set `busy_timeout = 5000` and `synchronous = NORMAL`, and switch to WAL only when the file is not already WAL.
- **Assessment saves recover.** An answer whose save failed before an assessment was closed is saved when it is reopened; answers in the error state (network, 5xx, or a 409 that survived the version retry) are retried with backoff.
- **Assessments auto-save and count down.** `<NoriAssessment />` saves each answer automatically (debounced, flushed on blur and before submit) with a per-item saved/saving indicator, so submit grades every answer. Timed assessments tick each second as `mm:ss` from the server deadline and lock at expiry, when the sidecar finalizes them as `expired`.
- **Client timeouts, shared connection and offline recovery.** `NoriClient` times out each request (10 s; 100 s for LLM-backed feedback and tutor calls), dedupes identical in-flight GETs, tracks connection state, and retries with backoff while offline. Islands share one client per page via `getSharedNoriClient`, treat a successful data call as the health check, and `<NoriPractice />` re-sends unsent local drafts (`resendLocalDrafts`) when the sidecar answers again.
- **Assessment saves are per item.** An answer the sidecar rejects (e.g. over 20,000 characters) is marked on that item with the reason and no longer holds back the other answers; network failures are retried. Submit saves every valid answer and refuses, naming the item, only if one cannot be saved. Answer textareas have `maxLength` 20,000 with a character count near the limit. The countdown wakes on second boundaries and expires exactly at the deadline, which is anchored at request send time.
- **Idempotent attempts.** `POST /v1/practice/attempts` accepts an optional client-generated `id`; repeating it returns the stored attempt instead of inserting another (`409` if the id was used for another exercise or a different answer). `<NoriPractice />` reserves the id before sending and keeps it on any unsent draft, so a lost response, a retry or a second tab records each attempt once.
- **Sidecar idle timeout.** `Bun.serve` now sets `idleTimeout: 120` so LLM-backed calls (up to 90 s) are not cut off by Bun's 10 s default.
- **Honest code-check labels and accessibility.** Code checks that do not run the code (Python and other non-JS references) are labelled "Heuristic check, not executed" (`CodeVerificationResult.executed`). Exercise option groups and inputs are labelled by the rendered prompt instead of raw Markdown, and text inputs and keyed options show a visible focus outline.

## 0.1.0

- **Spaced recall, weak-spot queue & expanded exercise primitives (`/v1/review`, `<NoriReviewQueue />`).** Added `GET /api/nori/v1/review` (FSRS/SM-2-style streak & interval scheduling over `practice_attempts`), `<NoriReviewQueue />` React island with inline recall retries, and deterministic grading for `multiple_select` and `cloze` exercises alongside `multiple_choice`.
- **In-browser code verification (`verifyCodeInBrowser`).** Added client-side syntax/delimiter checking, reference-call & forbidden-token assertion checks, and sandboxed Web Worker execution for `[code]` exercises in `<NoriPractice />`.
- **Vault write-back recall digest (`/v1/digest`, `bun run digest`).** Added `GET /api/nori/v1/digest` and `src/cli/digest.ts` CLI to export Obsidian/Apricot-ready Markdown recall digests from the sidecar API or directly from SQLite.
- **Modular SDK components & Miku workbench theme.** Modularized `src/sdk/components/` (`NoriPractice`, `NoriAssessment`, `NoriTutor`, `NoriReviewQueue`, `markdown`, `icons`) and added `resolveNoriIslandProps` for Archify-style vault path inference.

## 0.0.1

Initial MVP release of Nori as a pure embeddable practice SDK and headless SQLite/LLM sidecar for personal static learning sites.

- **Headless sidecar v1 API (`/api/nori/v1`).** `make sidecar` (`bun run src/sidecar-server.ts`) serves `/v1/health`, `/v1/practice/*`, `/v1/assessments/*` (server-clock timed/untimed assessments with expiry across restarts), and `/v1/tutor` (scoped attempt context, 256 KB body limit, 120,000-char context budget, untrusted-data framing, and deduplicated lesson text storage). See [docs/sidecar-api.md](docs/sidecar-api.md). ([#7](https://github.com/azusachino/nori/pull/7), [#8](https://github.com/azusachino/nori/pull/8))
- **Drizzle ORM & SQL migrations.** Schema lives in `src/lib/server/schema.ts` with generated SQL migrations in `drizzle/0000_sidecar_init.sql`, applied automatically on startup over `bun:sqlite` in WAL mode (`VACUUM INTO` online backup). ([#8](https://github.com/azusachino/nori/pull/8))
- **Single-package SDK (`.`, `./react`, `./styles.css`).** Exports `NoriClient`, `computeContentHash`, `checkMultipleChoice`, `localStorage` draft helpers, client-side `formatAttemptsAsMarkdown`, and `<NoriPractice />`, `<NoriAssessment />`, and `<NoriTutor />` React islands with scoped theme-token CSS. Declares `react` and `react-dom` as `peerDependencies` and `drizzle-orm` as the sole runtime dependency. ([#7](https://github.com/azusachino/nori/pull/7), [#8](https://github.com/azusachino/nori/pull/8))
- **Container image.** Added multi-stage `Containerfile` (`oven/bun:1-alpine` build + minimal runtime stage with `tini` as PID 1 and non-root `bun` user, leaving probes and PVC mounts to Kubernetes) and `.dockerignore`. ([#8](https://github.com/azusachino/nori/pull/8))
